Both branches start at fork/kern-0138 (`bad6ead`); kern-0140 contains kern-0139.
No phone operation was performed. Patches 0133–0138 were not changed.

## 0139: delayed panic

Boot arguments: `sweetpanic_test=60 sweetreset=1 sweetpanicwait=3`.
Default `sweetpanic_test=0` allocates nothing and does not arm a call.
The delay starts when the EARLY_BOOT thread call is armed, as with 0136.
The callback calls exactly `panic("sweetpanic_test")`; 0133/0134 own reset.
For an isolated panic-path test use `sweetwdt=0` so a watchdog bite cannot
be mistaken for successful panic reset. Hardware success is still untested.

Exact new log formats:

```text
SWEET PANIC TEST: armed, panic in %u s
SWEET PANIC TEST: not armed: thread_call allocation failed
```

For 60 seconds the arm line is `SWEET PANIC TEST: armed, panic in 60 s`.
Existing reset log expected after the panic is `SWEET RESET: panic -> fastboot (PON ... -> ...)`.

## 0140: opt-in lito USB2 cold power-up

Boot arguments: `sweetusb=2 sweetusbinit=27`. Mask **16 / 0x10** is the
next mask after existing 1/2/4/8, not bit-index 16. Default stays **11**.
Disable the new path with `sweetusbinit=11`; `sweetusb=1` stays read-only.
The cold path votes all three rails even if `sweetusbrails=0`: power-up
requires them; that older argument still controls the later 0113 vote.

The ABL guard runs before any new power-up write and before 0135 clock enables.
It reads GSNPSID only with GDSC, master, config-NoC and mock_utmi on; valid
DWC3 signature returns immediately with:

```text
SWEET USB: power-up: already up, skipping
```

All new configuration MMIO writes use this exact format, with the step names below:

```text
SWEET USB: power-up: %s +0x%05x 0x%08x -> 0x%08x
```

Other exact new log formats (`%...` are runtime values):

```text
SWEET USB: power-up: RCG %s CMD 0x%08x CFG 0x%08x (%s)
SWEET USB: power-up: DWC3 map failed, aborting
SWEET USB: power-up: guard GDSC 0x%08x mock_utmi 0x%08x GSNPSID 0x%08x
SWEET USB: power-up: already up, skipping
SWEET USB: power-up: guard GDSC 0x%08x master 0x%08x mock_utmi 0x%08x cfg 0x%08x; GSNPSID not read (gated)
SWEET USB: power-up: MMIO map failed, aborting
SWEET USB: power-up: EUD 0x%08x (read only)
SWEET USB: power-up: EUD enabled, aborting (CLO guard)
SWEET USB: power-up: rail L5 vote 880 mV result %d
SWEET USB: power-up: rail L12 vote 1800 mV result %d
SWEET USB: power-up: rail L2 vote 3075 mV result %d
SWEET USB: power-up: rail vote failed, aborting
SWEET USB: power-up: GDSC STILL OFF 0x%08x, aborting
SWEET USB: power-up: GDSC on 0x%08x -> 0x%08x
SWEET USB: power-up: RCG timeout, aborting
SWEET USB: power-up: %s 0x%08x -> 0x%08x (%s)
SWEET USB: power-up: omitted REFCLK_SEL: mainline/CLO mask-value disagreement, +0xa0 0x%08x unchanged
SWEET USB: power-up: omitted SIDDQ: absent from CLO msm-4.19 layout
SWEET USB: power-up: complete GSNPSID 0x%08x (%s)
SWEET USB: power-up: omitted SS PHY/PIPE and ahb2phy: USB2 DT clock list only
SWEET USB: power-up: failed, gadget not started
```

Every cold-path write reports its before/after value; GDSC, RCG and branches
also report completion or timeout. RPMh rail calls expose status, not PMIC
voltage registers: their return codes are logged, with no fabricated readback.

Omitted steps and reasons:

- REFCLK_SEL write: both drivers define offset 0xa0/mask 3/value 2, but the
  mainline init call reverses mask/value. Retain hardware state and log it.
- SIDDQ: mainline-only COMMON0 bit 2 has no CLO/OnePlus definition or init write.
- SS PHY/PIPE and rain ahb2phy branch: USB2 uses UTMI-as-PIPE; lito's six
  controller clocks are used, and no lito ahb2phy offset was sourced. Existing
  0135's later pipe handling is unchanged.
- Rain's extra GCTL assignment: existing 0132 performs global/device init later.
- Optional RCAL/debug tuning/EUD-disable/PLL-CX reprogramming: no lito-specific
  values requested or verified; preserve them. A nonzero EUD aborts as in CLO.

The complete register-value-to-source mapping (URLs, immutable commits and
line anchors) is in [CONSTANTS.md](../avicii/CONSTANTS.md#usb-cold-power-up-0140-pinned-source-ledger).
This includes the fetched CLO msm-4.19, mainline and OnePlus PHY comparisons.
